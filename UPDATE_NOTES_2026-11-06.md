# ScholarshipHive — targeted follow-up update (2026-11-06)

## Included

- Department Head (Marketing, Processing, Counselors) and Country Head credentials accepted for leave and custom-shift requests. Password approval/active status still checked; these requests do not check attendance Wi-Fi.
- Same user/date pending leave is superseded when a newer leave is submitted; the old record remains with `Superseded` status, while the newer request includes the previous and new reasons. Heads cannot approve their own requests through JWT admin API.
- Fixed web Team/Staff list omission of HeadOfCounselors.
- Admin portal brand/logo is a home link; heads and reception are routed to their own landing pages. Icons added to text-only navigation labels.
- Department Heads have Account Settings (password and fingerprint enrollment) in mobile. Country Head likewise.
- Heads can deactivate *only* employees in their authorized department via separate scoped web and mobile endpoints. This is a soft removal by `IsActive=false`, preserving attendance/report history, not irreversible deletion.
- Reception visitors have a pale green background while checked in; their rows return to white after checkout (web and Flutter).
- Responsive mobile navigation labels on narrow screens.
- New read-only `/ActivityLog` portal for owner/admin/auditor, capturing future entity additions, modifications and deletions. No secret field values are stored. Old activity cannot be reconstructed. Activities generated by background workers may say `System`.
- Corrected existing `AddUserNotices` migration's C# syntax (`CREATE INDEX`).

## IMPORTANT: not solved / needs real devices and application validation

- Existing approved router records are persisted in the database; university Wi-Fi may roam between AP BSSIDs. Do not whitelist all APs blindly. Verify each intended office router BSSID; repeated router approvals may be due to roaming or using a new SQLite database after ZIP extraction.
- Android permission prompts are OS-controlled. Existing onboarding code checks grants, but lack of `Allow all the time`, battery-exemption being revoked, or reinstall/new device can prompt again. No permission bypass was added.
- Flutter yellow overflow lines and red assertions require an exact stack trace/widget route to prove all cases fixed; a narrow-screen nav improvement was made but exhaustive device testing is not done.
- Audit log captures EF changes made through the normal `SaveChangesAsync` path after this update. It does not include earlier activity or SQL changes executed outside EF, and should not be treated as a tamper-proof compliance trail. No comprehensive audit/export policy provided.
- Do not deploy to production without testing authorization, migrations, head leave/shift submission, audit events, role revocation and Android/UI workflows.
- Full .NET/Flutter SDK is unavailable in this working environment; archive integrity and code-focused checks only. Run `dotnet build` and `flutter analyze --no-pub` on your Windows PC.

## How to run

From project root, in backend terminal:

```powershell
cd backend\ScholarshipHive.Server
dotnet restore
dotnet build
dotnet run
```

Second terminal:

```powershell
cd mobile
flutter pub get
flutter analyze --no-pub
& "C:\Android\Sdk\platform-tools\adb.exe" devices
& "C:\Android\Sdk\platform-tools\adb.exe" -s <ACTUAL_DEVICE_ID> reverse tcp:5080 tcp:5080
flutter run -d <ACTUAL_DEVICE_ID> --dart-define=API_SERVER_URL=http://127.0.0.1:5080
```

## Data safety

Back up your *working* `ScholarshipHive.dev.db` and server secrets before running a newly extracted project. Do not blindly overwrite live database with a packaged sample database.
